# Environment variables

Set serving variables before starting `enginesrv`, unless an entry says otherwise. Some are read per call or at engine or session creation.
The API key variable is not listed here: its name comes from `api_key_env` in the [configuration file](configuration.md).

Two kinds of values appear below:

- A **switch** that is unset keeps its default. A switch that is set is on only for `1`, `true` or `on` (surrounding spaces and letter case are ignored); any other value turns it off.
- A variable with **accepted values** refuses startup when set to anything else, unless the table says otherwise.

## Build

| Variable | Default | Meaning |
| --- | --- | --- |
| `INFERENCE_CUDA_ARCHS` | `86` (`72` on aarch64) | Comma-separated native GPU architecture targets for CUDA kernels, read by `cargo build --features native-cuda`. For example, `75,86,89` targets RTX 20, 30 and 40 series with CUDA 12.4. The build also includes PTX for the highest listed target, which a suitable newer driver may compile for a newer GPU; PTX does not run on an older architecture. CUDA 12.8 or newer is needed to compile a native `120` target for RTX 50 series. These targets and PTX compatibility do not by themselves qualify the engine on a GPU. See [CUDA FP16 prefill attention](configuration.md#cuda-fp16-prefill-attention). |

NVIDIA documents the [GPU compute capabilities](https://developer.nvidia.com/cuda/gpus), [PTX compatibility rules](https://docs.nvidia.com/cuda/archive/12.8.1/blackwell-compatibility-guide/index.html), and [CUDA 12.8 compiler support for SM 120](https://docs.nvidia.com/cuda/archive/12.8.2/cuda-features-archive/index.html).

## Server

| Variable | Default | Meaning |
| --- | --- | --- |
| `ENGINESRV_WARM_TURNS` | on (switch) | With `prefix_reuse`, remember the last conversation's tokens so that the next turn only tokenizes its new messages. A request from another conversation replaces the memory. |
| `ENGINESRV_PREFIX_BLOCK_MATCH` | on (switch) | With `prefix_reuse`, also save one block checkpoint, cut at a multiple of `ENGINESRV_PREFIX_BLOCK_TOKENS` tokens just before the end of the conversation, so a prompt that changes only near its end can still reuse most of it. Used by engines that keep at least two saved prefixes. |
| `ENGINESRV_PREFIX_BLOCK_TOKENS` | 4,096 | Spacing of the cut points, in tokens. Values below 1 select the default. |
| `ENGINESRV_CACHE_USAGE` | on | Report reused prompt tokens in the API usage fields. Once set, only the exact values `1`, `true` and `on` keep it on. |
| `ENGINESRV_THINK_REPLAY` | on (switch) | Qwen3.6 only: keep the reasoning that clients resend with earlier assistant turns in the prompt. Off removes it for every engine. |
| `ENGINESRV_NOTICE_TOOLWRAP` | on (switch) | Qwen3.6 only, with think replay on: render system messages that follow an assistant turn as tool responses, so that the chat template keeps the reasoning of earlier tool-calling turns. |
| `ENGINESRV_SHADOW_BLOCK_LCP` | off (switch) | Read-only observation for the request log: report the longest common prefix the saved block checkpoint would have matched. Never changes restore or save behavior. |

| Variable | Default | Meaning |

| `FIFI_FLINT_CUDA_ALLOC_LAZY_RETURN` | off (switch) | With the allocation cache on, let a returned GPU block go idle without a device-wide synchronize while the engine has a single GPU stream; the next user of the block is ordered behind the old one by that stream. A host-synchronous write into a cached block, and the creation of a second stream, still synchronize first (once, and only if blocks went idle since the last synchronize). Output is unchanged. | `FIFI_FLINT_CUDA_EXPERT_CACHE` | unset (auto) | Where the routed experts of the MoE layers live. Unset: every expert stays on the GPU when `context_limit` fits that way, exactly as before. A longer context keeps all 256 experts of every layer in one page-locked host buffer (about 18 GiB for the EXL3 4.0 pack) and only as many per layer on the GPU as the free GPU memory leaves room for, after the other weights, the KV cache for `context_limit`, the work reserve and headroom. An expert that is not on the GPU is copied in from the host buffer and replaces the least recently used expert that the current prompt chunk or decode step does not use. Output is the same either way, because the weights and kernels are the same; fewer experts on the GPU cost a copy per miss. `1`, `true` or `on` always uses the host buffer, and then also leaves 160 MiB of the free GPU memory unused for the choice of all 256. `0`, `false` or `off` keeps every expert on the GPU and refuses a context that does not fit, naming the largest one that does; this is the rollback. | `FIFI_EXL3_CPU_ISA` | `auto` (strict) | Instruction set of the CPU kernel that computes EXL3 experts on the host (the `cpu_moe_*` keys of the `flint` object, see configuration.md); without a `cpu_moe_*` key no host expert kernel runs and the variable has no effect. `auto` takes AVX-512 (VBMI and VNNI) when the CPU has it, otherwise AVX2 with FMA, otherwise the scalar reference. `avx512`, `avx2` and `scalar` force one tier. | `FIFI_FLINT_LATE_HEALTH` | on (switch) | Check the model output for non-finite values on the GPU. |
| `FIFI_FLINT_TOKEN_HEALTH` | on (default; `0` rolls back) | Token-end health gate for single-row calls (decode and one-row prefill tails): unless it is turned off, armed calls clear the 49x2-word status ring (one 392 B write) at token start, park the per-frame FFN health words in it, skip the per-layer attention `Group::check`, and at the token end (before the head, sampling and KV append commits) do one sync and two ring reads replacing the per-frame status reads and their event syncs, reporting the earliest fault in execution order; error classes are unchanged and aborts keep the original refusal message unless a ring fault ran strictly earlier. A row is accepted when it is finite, has its low 16 bits clear and converts to a finite f16 (round to nearest even), the same rule and the same stored bits as the host path; a rejected row fails the token with the same error, checked once per token before sampling (once per prompt piece in layer-major prefill). Unset, `1`, `true` and `on` keep it on; any other value, including empty and non-UTF-8, turns it off. Read once at the first Flint CUDA engine load; restart to change. Rollback: `FIFI_FLINT_CUDA_KV_DEVICE_F16=0`. |
| `FIFI_FLINT_CPU_MOE_OVERLAP` | off | With the `cpu_moe_*` keys configured, overlap the CPU expert work with the device step. Resolved once, like the kernel switches above. |

The startup line reports `alloc_cache=`, `late_health=`, `token_health=`, `packed_pointwise=`, `grouped_gather=`, `q8_tiled=`, `kv_device_f16=` and `fused_publish=` (the q8-tile route resolves off on f16 engines). When armed it also ends with `alloc_return=lazy`.

## Nemotron 3.5 on NVIDIA CUDA

Nemotron serves greedy requests only on CUDA (sampled requests are refused). These switches select kernels and diagnostics; all default off unless noted:

| Variable | Default | Meaning |
| --- | --- | --- |

| `NEM35_CUDA_CHUNK_PREFILL` | `0` | With `NEM35_CHUNK_EXPERTS=gpu`: stream the routed experts in row groups of this many rows (capped by the chunk capacity). |

| `NEM35_NO_BATCH` | off | Kill switch for the legacy GPU batch expert kernel. |

## Tests

These are read by `cargo test`, not by `enginesrv`. A test that needs recorded data finds each location by name: the environment variable first, then the same key in the JSON object `~/.config/fifi/test-paths.json`. The tests that read them skip when a location is unset, and fail instead when `FIFI_TEST_REQUIRE_DATA` is exactly `1`. A deliberate `#[ignore]`d run always fails on a missing value. The qualification, benchmark and oracle harnesses read further variables (`FLINT_QUAL_*`, `DT_*`, `FIFI_GRAPH_BENCH_*`, `FIFI_FLINT_*_ORACLE*`, `FLINT_PROBE_*`, the `*_CHILD` child-process fault harnesses and the like); those are inputs of the harnesses, not serving switches.

| Variable | Default | Meaning |
| --- | --- | --- |
| `FIFI_EXL3_SWEEP_LAYERS` | `12` | For the ignored `flint_shape_rate_latency` timing test of the EXL3 CPU kernel (random weights of the Flint expert shape at every stored rate): how many layers of six experts the rounds cycle through. `1` keeps the six experts cache resident; the default exceeds the caches. Run `cargo test --release --lib flint_shape_rate_latency -- --ignored --nocapture` from `engine/`. |
| `M3_LAYOUT_DIR` | unset | The frozen layout directory of the EXL3-versus-GGUF quality comparison. The two default tests that load it skip when it is unset; the ignored `m3_compare` test requires it. |
| `M3_COMPARE` | unset | For the ignored `m3_compare` test: `P1:<candidate dir>:<reference dir>` or `O1:<candidate dir>:<reference dir>`, the two recorded sidecar sets to score. Run `cargo test --lib m3_compare -- --ignored --nocapture` from `engine/`. |
| `M3_REGISTRATION` | unset (refused) | For `m3_compare`: `v6` or `v7`, the registration version whose rule scores the pair. There is no default: an unset or unknown value stops the test before any sidecar is read, and every verdict names its version (see `qualification/o1-gate-v7/`). |
